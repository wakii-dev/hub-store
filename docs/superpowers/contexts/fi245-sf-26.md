## Spec slice
1. `POST /webhooks/orders` trên BFF: auth bằng **HMAC signature** header (`X-Signature`, secret qua env `WEBHOOK_HMAC_SECRET` — KHÔNG hardcode, .env.example cập nhật).
2. **Idempotency**: dedupe theo `externalId` (bảng `webhook_events` — source, externalId, payload JSONB, status, receivedAt; unique constraint) — replay cùng externalId → trả 200 + kết quả lần đầu (KHÔNG tạo đơn trùng).
3. **Mapping** payload → orders: cấu hình field-mapping qua env/JSON config (source-specific); validate như import SF-13 (địa chỉ, SĐT, items, COD); lỗi → 422 + errors[]; OK → insert orders (fulfillCode tự sinh, audit log, publish event `order.created` lên Kafka `order-events` qua producer của SF-27 — best-effort như mọi producer khác → SSE "đơn mới" + push hưởng tự động).
4. **Retry semantics chuẩn**: 2xx khi xử lý xong; 422 lỗi dữ liệu (caller sửa rồi gửi lại); 5xx chỉ khi lỗi hệ thống (caller retry, idempotency bảo vệ).
5. E2E spec: gửi webhook → đơn vào D1; gửi lại cùng externalId → không trùng; sai signature → 401.

## Webhook field mapping (Task 4 — sf-26)

Payload → `IntakeOrder` qua `lib/webhook-mapping.ts` (BFF). Default map: tên field payload = tên canonical (`externalId`, `customerName`, `customerPhone`, `customerAddress`, `items[{productCode,productName,quantity}]`, `codAmount`, `shopHint`). Override flat rename 1 mức qua env `WEBHOOK_MAPPING` (JSON `{canonical: payloadField}`, vd `{"externalId":"orderNumber"}`) — JSON invalid → warn-once + default (không crash boot). `quantity` TỰ TÍNH = Σ items[].quantity; `codAmount` string-số được coerce. Validate: externalId/customerName/customerAddress bắt buộc, SĐT khớp `^(\+84|0)\d{9}$` (đồng bộ IntakeValidator.java), items mảng không rỗng, mỗi item quantity nguyên >= 1 → lỗi gom tất cả → 422 `VALIDATION_ERROR` + `details[] {field, message}` (ErrorDetail shared FROZEN — không có `row`). Header `X-Source` chỉ cho phép `[A-Za-z0-9._-]` (ASCII-safe cho gRPC metadata; convention caller dùng lowercase, vd `shopee`, `tiktok`).

**Known limitations**: KHÔNG có rate-limit trên `/webhooks/orders` (caller tự throttle); KHÔNG retention cho bảng `webhook_events` (dedupe rows tích lũy vô hạn — cần job dọn sau).
