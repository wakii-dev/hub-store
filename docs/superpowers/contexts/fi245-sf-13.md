# FI-245 SF-13 Context Pack — Order intake + delivery exceptions
> Epic spec: docs/superpowers/specs/ict-service-support-postgres-prod-spec.md §3.13. Bracket: docs/superpowers/brackets/fi245-postgres-production.md. Tier 2 — deps SF-2 + SF-3 Done.

## Spec slice
1. **Import đơn CSV/Excel**: (a) endpoint template tải về (headers khớp fields OrderSeed: khách, SĐT, địa chỉ, items, quantity, COD, region/shopHint); (b) upload → validate server-side → trả preview `{valid[], errors[{row, column, message}]}`; (c) confirm → batch insert vào orders (generated fulfillCode `ORD-*` tiếp dải, createdTime = now). Chỉ Coordinator.
2. **Tạo đơn thủ công**: form "Tạo đơn" trên D1 (modal) — cùng validation; sau tạo → đơn hiện ngay trong list.
3. **fulfillCode generation**: tiếp dải ORD-* hiện có trong DB (max + 1 hoặc sequence — chọn 1, atomic); KHÔNG đụng dải BATCH-*.
4. **Per-order FAILED + lý do**: enum lý do (KHACH_VANG / SAI_DIA_CHI / KHACH_TU_CHOI / KHAC) + ghi chú tự do — RPC MỚI additive (không phá message cũ); thao tác từ D2 WarehouseOps; đơn trong batch đã hoàn tất vẫn mark-fail được từng đơn.
5. **Giao lại**: đơn FAILED → tạo retry (đơn MỚI link oldOrderId + audit) — CHỌN cách này (reopen state làm vỡ history); retry đơn xuất hiện lại D1 queue.
6. Audit: mọi intake/exception mutation ghi activity_log (SF-7 pattern — deps: nếu SF-7 chưa merge thì ghi thẳng bảng, pattern thống nhất).
7. E2E specs MỚI: import happy-path + lỗi validation; tạo đơn thủ công; mark-fail + giao lại.

## ACCEPTANCE (user-visible)
- Tải template → điền 10 đơn (2 dòng lỗi cố tình) → upload → preview chỉ ra 2 lỗi đúng cột → confirm → 8 đơn vào D1.
- Tạo đơn thủ công → hiện ngay trong list, code ORD-* mới đúng dải.
- Hoàn tất batch → mark 1 đơn FAILED + lý do → nút giao lại → đơn retry mới trong D1, link về đơn cũ, audit log ghi cả 2.
- E2E cũ 13 specs + specs mới toàn xanh.
