# FI-245 SF-14 Context Pack — COD đối soát
> Epic spec: docs/superpowers/specs/ict-service-support-postgres-prod-spec.md §3.14. Bracket: docs/superpowers/brackets/fi245-postgres-production.md. Tier 3 — deps SF-7 (activity/export pattern) + SF-13 (FAILED/retry — settlement chỉ tính đơn thật sự giao).

## Spec slice
1. **COD confirm per-order**: khi đơn hoàn tất có COD > 0 → trạng thái thu `PENDING`; xác nhận thu (số tiền thực thu, người thu = username hiện tại, thời điểm) qua RPC/REST MỚI additive; xác nhận hàng loạt theo batch (shipper nộp tiền cả chuyến → confirm cả batch 1 lần).
2. **Settlement storage**: Flyway V3 DB `fulfillment` — bảng `cod_confirmations` (orderId, batchCode, expectedAmount, collectedAmount, collectedBy, collectedAt) hoặc fields trên orders — CHỌN bảng riêng (giữ orders schema ổn định).
3. **Màn đối soát theo shop** (Manager): chọn kỳ (ngày/mốc thời gian) → bảng per shop: tổng đơn hoàn tất, tổng COD kỳ vọng, tổng đã thu, chênh lệch; drill-down đơn lệch (đã hoàn tất chưa xác nhận thu / lệch số tiền).
4. **Export đối soát CSV** theo pattern SF-7 (stream, content-type, tên file có kỳ).
5. Chỉ đơn status hoàn tất (KHÔNG tính FAILED/retry-chưa-xong) vào kỳ đối soát; retry thành công tính 1 lần trên đơn retry.
6. E2E spec mới: hoàn tất batch có COD → confirm → đối soát số khớp psql.

## ACCEPTANCE (user-visible)
- Hoàn tất chuyến có COD → màn D2 hiện "chờ thu" → confirm cả chuyến 1 lần → trạng thái đổi.
- Manager mở đối soát: tổng theo shop khớp psql GROUP BY (verify tay được); đơn lệch hiện rõ.
- Export CSV mở Excel được, số khớp màn hình.
- E2E cũ + mới toàn xanh.

## Boundary (KHÔNG làm)
- KHÔNG thanh toán online/gateway — chỉ tiền mặt + xác nhận.
- KHÔNG đối soát đa kỳ phức tạp / khoán kỳ tháng — kỳ theo ngày/mốc là đủ.
- KHÔNG đụng batching DB.
- KHÔNG sửa specs E2E cũ.
