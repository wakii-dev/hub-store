## Spec slice (SF-4 chịu trách nhiệm)

1. **Deployments ×5 + Services ×5 ClusterIP** — thay nội dung placeholder dirs
   `k8s/base/apps/{fulfillment,batching,print,bff,web}/` (SF-1 tạo). KHÔNG sửa base kustomization.
   Ports: fulfillment 50051, batching 50052, print 50053, bff 8080, web 3000.
2. **Env wiring** (giá trị verify từ services/bff-gateway/src/config.ts + docker-compose.yml):
   - bff: `GRPC_FULFILLMENT=fulfillment:50051`, `GRPC_BATCHING=batching:50052`,
     `GRPC_PRINT=print:50053` (host:port form đã hỗ trợ sẵn), `JWT_DEV_SECRET` từ Secret
     `jwt-dev-secret` (SF-1), seed không cần cho bff.
   - fulfillment: `SEED_PATH` → file từ ConfigMap seed (SF-1) mount vào pod.
   - batching: `CANONICAL_SEED_PATH` + `FULFILLMENT_ADDR=fulfillment:50051`.
   - print: `PRINT_SERVICE_SEED_PATH`.
   - web: giữ build-time rewrite remotes như Dockerfile.web hiện có (không cần env runtime).
3. **Probe wiring (CHỈ manifest — endpoints do SF-2 tạo):** gRPC readiness/liveness qua
   grpc.health.v1 cho 3 services (probe type grpc trên đúng port); bff httpGet `/healthz`;
   web httpGet `/healthz`.
4. **Batching boot-order (P0 P0-analysis rủi ro #1):** initContainer busybox `nc -z fulfillment
   50051` loop, timeout fail-loud 120s (KHÔNG retry vô hạn). KHÔNG sửa Go dial code.
5. **`imagePullPolicy: IfNotPresent`** trên TẤT CẢ deployments (images build local bằng minikube).
6. **Ingress** (networking.k8s.io/v1): `/` → web:3000, `/api` → bff:8080 với rewrite strip prefix
   (nginx BFF phục vụ route không có `/api`), `/keycloak` → keycloak:8080 (prefix env do SF-3 đặt).
   Rewrite-target annotation theo class ingress minikube (nginx).
7. **Overlay minikube glue** (`k8s/overlays/minikube/`): namespace, commonLabels, images tags
   `hub-store/*:dev`, replica=1 mỗi service. NodePort fallback = KHÔNG dead-config trong overlay
   (ghi doc ở SF-5).
8. **`scripts/k8s-deploy.sh`** — CALL `scripts/k8s-build-images.sh` (SF-1 — KHÔNG duplicate build
   logic) → `kubectl apply -k k8s/overlays/minikube` → `kubectl rollout status` từng deployment →
   idempotent re-run được (apply lại sạch).
9. **Smoke curl qua ingress**: lấy minikube ip + host, curl `/`, `/api/healthz` (qua ingress),
   một remoteEntry `/remotes/orders/remoteEntry.js` → 200.

## ACCEPTANCE (user-visible)

- `bash scripts/k8s-deploy.sh` chạy sạch 1 lệnh → TẤT CẢ pods Ready (rollout status không timeout),
  chạy LẠI lần 2 vẫn sạch (idempotent).
- Mở `http://<minikube-ip>/` (hoặc host qua /etc/hosts) → shell app load, remoteEntry orders +
  fulfillment load được, login fake-JWT vào được D1.
- Batching pod KHÔNG crash-loop (initContainer đợi fulfillment sẵn sàng).
- Pods bị OOM/restart tự phục hồi đúng probe (readiness Serving sau seed).
