## Spec slice (SF-5 chịu trách nhiệm)

1. **Playwright config env-driven** (SF-5 sở hữu `e2e/playwright.config.ts`): đọc
   `E2E_BASE_URL` — KHÔNG set → giữ nguyên hành vi hiện tại (baseURL http://localhost:3000 +
   webServer boot-all.sh, reuseExistingServer như cũ); SET → baseURL = giá trị đó + SKIP
   webServer. **Regression criterion bắt buộc (P1 plan-critic):** bare `npx playwright test`
   không env vẫn pass như trước local.
2. **Cluster E2E pass**: chạy spec hiện có với `E2E_BASE_URL=http://<ingress>` → specs chính
   pass (fake-JWT auth flow qua ingress — login D1, batch, print).
3. **gRPC integration check trong cluster**: kubectl run job/pod (grpcurl image hoặc node script)
   gọi health + một RPC nghiệp vụ qua Service DNS — chứng minh graph BFF→backends hoạt động
   in-cluster.
4. **Keycloak token smoke QUA INGRESS** (không port-forward): curl password grant qua
   `http://<ingress>/keycloak/...` → access_token (route từ SF-4 + prefix env từ SF-3 hội tụ).
5. **Postgres persistence proof**: ghi data (tạo table/insert test hoặc dùng db seed nếu có) →
   `kubectl delete pod postgres-0` → pod mới lên → data còn. (Proof cụ thể spec yêu cầu —
   KHÔNG dùng rollout restart làm bằng chứng.)
6. **Kafka produce/consume round-trip (SC-6 — convergence proof, SF-1 chỉ provision broker)**:
   kubectl run kafka client pod (DÙNG CÙNG image tag SF-1 pin — không drift) → produce 1 message
   vào topic CONTRACT `orders.events` → consume lại thấy đúng message. Đây là bằng chứng Kafka
   dùng được end-to-end trong cluster, đồng thời chứng minh advertised-listener contract SF-1
   đúng (client kết nối qua `kafka:9092` Service DNS — không phải pod DNS). Nếu round-trip fail
   vì advertised listeners sai → đó là bug SF-1, flag về epic chứ không tự patch manifest SF-1
   ngoài boundary.
7. **Seed-update workflow doc**: seed JSON đổi → rebuild configmap (configMapGenerator hash đổi
   qua apply -k) + rollout restart deployments ăn seed.
8. **README deploy guide đầy đủ**: minikube start (preflight) → deploy.sh → URLs → e2e cluster;
   + **NodePort fallback doc** (phương án khi ingress addon không hoạt động theo driver).
9. **FI-245 wiring doc + Kafka wiring slot doc**: khi code FI-245 (Postgres repos, OIDC login)
   merge — bật env nào trên overlay nào (datasource URLs tới postgres DBs, OIDC authority/client
   tới keycloak ingress), thay realm minimal bằng realm đầy đủ FI-245 ở đâu; khi code event-flow
   merge (story sau) — `KAFKA_BOOTSTRAP_SERVERS=kafka:9092` + topics cần tạo.
10. **Security notes**: mọi secrets trong k8s/ là dev-only (base64 không phải bảo mật), không
   secret thật được commit; ingress expose gì ra host; Kafka KHÔNG auth (dev-only — ghi rõ).
11. **Final audit comment lên epic FI-272**: map SF → merge hash → bằng chứng từng success
    criteria (1)-(6) của epic spec.
