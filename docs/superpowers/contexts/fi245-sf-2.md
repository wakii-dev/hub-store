> Đọc file này THAY VÌ tự tổng hợp. Epic spec: docs/superpowers/specs/ict-service-support-postgres-prod-spec.md. Bracket: docs/superpowers/brackets/fi245-postgres-production.md.

## Spec slice (SF-2 chịu trách nhiệm)
1. **Flyway orders schema V1** (trong `services/fulfillment-service/src/main/resources/db/migration/`): bảng `orders` (mọi field `SeedModels.OrderSeed` + surrogate id), `shop_assignment_history` (order FK, timestamp, action, note), `regions`, `delivery_staff`. Natural key `fulfillCode` UNIQUE.
2. **`PostgresOrderRepository implements OrderRepository`** — 11 method giữ ĐÚNG semantics in-memory:
   - `filter`: mọi điều kiện thành SQL; region filter GIỮ heuristic substring (`customer_address LIKE` + **escape %/_** — task riêng trong plan); ORDER BY tường minh khớp in-memory (createdTime, fulfillCode); `FilterResult` invariant = **1 query duy nhất với `COUNT(*) OVER()`** (KHÔNG 2 statement trong transaction READ COMMITTED — vẫn race).
   - `findByFulfillCode`: match CẢ `ORD-*` lẫn `RSA-*` (fix FI-237 giữ nguyên — task riêng, đừng bỏ sót khi viết impl mới).
   - `findByCodes`: trả đúng thứ tự codes yêu cầu, bỏ code lạ → CASE-based ORDER BY hoặc post-sort.
   - `mutateBatchStatus` (nhiều codes, target 0/1/2; target=0 clear batchCode): **1 transaction**; code lạ skip như hiện tại.
   - `assignShopHub` + append history; `getHistory` ORDER BY timestamp + tie-breaker ổn định.
   - `updateDeliveryTime`, `updateNote`: replace-field tương ứng `withX` record semantics.
   - `distinctShops`: DISTINCT SQL từ orders, sort theo shopCode (khớp in-memory derive).
3. **Flyway migrate-on-boot** (Spring Boot boot path); Hikari pool; `application.yml` datasource qua env (`FULFILLMENT_DB_*` / JDBC URL).
4. Boot: seed-verify — DB rỗng → log hướng dẫn chạy seed pipeline SF-1 (KHÔNG tự seed data — pipeline thuộc SF-1); fail-loud nếu rỗng và `STRICT_SEED=1`.
5. **Chọn impl**: `@ConditionalOnProperty(name="fulfillment.store", havingValue="postgres", matchIfMissing=true)`; `inmemory` chỉ trong unit test context. Runtime thiếu datasource → **fail-loud khi start**.
6. `run.sh`: wait-for-db (pg TCP) rồi start.
7. Unit tests GIỮ `InMemoryOrderRepository` (3 file test hiện có chạy tiếp, không testcontainers); thêm integration test chạy khi postgres có sẵn (skip-if-no-DB qua env).

## ACCEPTANCE (user-visible)
- Standalone flow: `docker compose up -d postgres orders-migrate` (wiring SF-1) + `bash scripts/seed-db.sh` → `psql` DB fulfillment thấy ORD-3001… + regions + staff + history seed.
- Service lên với Postgres: `filter` trả cùng kết quả như in-memory cùng seed (so E2E list/filter), paginate đúng, total khớp (kể cả khi có mutation xen giữa — window count).
- Tạo batch mutation (qua Go) → status batch đổi VÀ persist (`psql` SELECT thấy; restart service còn).
- History append sau assignShopHub → `getHistory` trả đủ + đúng thứ tự.
- `mvn test` pass KHÔNG cần DB (unit); integration test tự skip khi không có DB.
