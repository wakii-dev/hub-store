## Spec slice (SF-4 chịu trách nhiệm)
1. **Keycloak realm import** (`docker/keycloak/hubstore-realm.json` — mount dir do SF-1 chuẩn bị): realm `hubstore`; roles `Coordinator`/`WarehouseOps`/`Manager` (khớp role matrix shell `apps/shell/src/nav.ts`); public client `hubstore-web` (PKCE, standard flow, redirect `http://localhost:3000/*`); users mẫu mỗi role 1 user. **Password trong realm JSON là LITERAL dev-only — CẤM env-substitution** (`--import-realm` skip realm tồn tại nên env đổi cũng vô tác dụng; đổi password = reset keycloak volume). Pin Keycloak image version + `oidc-client-ts` version (trong task shell-login-pkce). Issuer port/env khớp wiring SF-1 (`OIDC_ISSUER=http://localhost:8081`) — KHÔNG sửa compose.
2. **Shell login**: wire OIDC redirect PKCE qua `VITE_OIDC_AUTHORITY/CLIENT_ID/REDIRECT_URI` (đã commented trong `.env` — uncomment + set giá trị); silent renew (oidc-client-ts hoặc tương đương); logout; 401 → redirect login. Login UI thay dev-stub 1-click (giữ UX đơn giản: username/password form redirect Keycloak).
3. **BFF verify JWKS**: thay HS256 shared-secret verify cho user flow bằng JWKS (env `OIDC_ISSUER` — khớp claim iss, `OIDC_AUDIENCE`, và `OIDC_JWKS_URL=http://keycloak:8081` — URL INTERNAL trong network compose để fetch keys; wiring SF-1 authored, KHÔNG sửa compose); **refresh JWKS cache khi gặp unknown `kid`**; map roles claim `realm_access.roles` → `x-user-role` metadata gửi gRPC (services KHÔNG đổi — vẫn nhận x-user-role, M-3 note để sau).
4. **Fake-JWT dev-stub**: loại khỏi runtime path (`packages/shared/src/auth` signFakeJwt không còn được runtime dùng); GIỮ cho unit test mock.
5. **Forgot-password C1 (dev-only)**: FE custom page "Forgot password" trên shell (cùng design language, KHÔNG đụng business logic) — user nhập username + password mới trực tiếp (KHÔNG email, KHÔNG OTP) → BFF endpoint (vd `POST /auth/reset-password`) gọi Keycloak Admin API set password mới. BFF cần admin credential (service account hoặc admin env — KHÔNG hardcode, env qua .env.example SF-1). **DEV-ONLY bắt buộc ghi rõ**: không có bước xác minh danh tính → comment đầu endpoint + README "production cần OTP email hoặc Keycloak built-in forgot-password". Page KHÔNG đổi testid/DOM mà E2E phụ thuộc (page mới, không sửa page cũ).
5. **E2E login helper**: Playwright global-setup login UI Keycloak 1 lần → `storageState` reuse cho 13 specs; helper re-login khi token hết hạn. KHÔNG ROPC. Specs business assertions KHÔNG đổi.

## ACCEPTANCE (user-visible)
- Mở :3000 → redirect Keycloak → đăng nhập user thật (username/password) → về shell đúng firstPathForRole theo role.
- 3 role khác nhau thấy đúng route chặn/sợ (role matrix hiện giữ nguyên).
- Token hết hạn → silent renew không bắt user login lại; logout → về màn login.
- Gọi API không token / token sai → 401; token role Manager → bị chặn route không permitted (như trước).
- E2E suite chạy qua login thật.
