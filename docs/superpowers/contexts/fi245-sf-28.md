# FI-245 SF-28 Context Pack — D1 order ops: chuyển kho CN + delivery time + criteria
> Epic spec: docs/superpowers/specs/ict-service-support-postgres-prod-spec.md §3.28. Bracket: docs/superpowers/brackets/fi245-postgres-production.md. Tier 3 — deps SF-2 (orders Postgres) + SF-13 (order intake).

## Spec slice
1. **Chuyển kho CN** (Java fulfillment): chọn đúng 1 đơn trên D1 → chặn đơn tách nợ (split-debt flag) → modal đề xuất kho đích (suggest endpoint, debounce search, radio list) → xác nhận tạo **yêu cầu chuyển kho** (ticket: từ kho, đến kho, lý do, trạng thái chờ duyệt) → cột/indicator trên D1 row hiện ticket chuyển kho + badge trạng thái; modal **lịch sử ticket chuyển kho** (bảng: ticket #, trạng thái duyệt, kho đích, lý do, thời gian + người xác nhận). Flyway migration mới (transfer_tickets). Audit log từng lần tạo/duyệt.
2. **Điều chỉnh thời gian dự kiến giao** per-order: modal DatePicker + slot giờ lấy từ API `time-delivery` (slots theo ngày); chặn chọn ngày quá khứ; lưu → audit log + D1 row update (SSE hưởng qua Kafka event `order.updated` nếu Kafka on — best-effort).
3. **Criteria presets tạo phiếu** (step 1 wizard D1b): endpoint trả danh sách presets tiêu chí tối ưu (vd: ngắn nhất, ưu tiên COD, ưu tiên số dừng...) — wizard D1b thêm step 1 radio chọn preset trước khi vào kế hoạch soạn; preset KHÔNG đổi logic DnD step 2 (chỉ metadata đi kèm phiếu); KHÔNG đổi proto cũ (endpoint mới).
4. **Order note per-order** ("kho ghi chú"): nếu rebuild chưa có endpoint PUT note → thêm (validate, audit log); đã có thì KHÔNG làm lại — chỉ verify.
5. Roles: chuyển kho/adjust/note = Coordinator nhóm (Coordinator/SubCoordinator/FulfillmentStaff — theo matrix); role khác ẩn nút + API 403.

## ACCEPTANCE (user-visible)
- Chọn 1 đơn → chuyển kho CN → modal gợi ý kho → xác nhận → row hiện badge ticket; mở lịch sử thấy ticket với lý do + trạng thái.
- Điều chỉnh thời gian dự kiến giao → chọn slot từ ngày mai → row cập nhật; chọn ngày quá khứ bị chặn.
- Tạo phiếu soạn → bước 1 hiện radio tiêu chí tối ưu → chọn → kế hoạch soạn như cũ.
- Non-Coordinator không thấy nút; gọi API → 403. E2E cũ + mới xanh.

## Boundary (KHÔNG làm)
- KHÔNG flow duyệt ticket chuyển kho phức tạp (tạo + xem lịch sử là đủ; duyệt = giữ đơn giản).
- KHÔNG đụng flow tạo phiếu DnD step 2/3 (SF-16 sở hữu carrier section).
- KHÔNG đổi gRPC proto cũ — endpoint mới thôi.
