# FI-245 SF-10 Context Pack — Realtime SSE
> Epic spec: docs/superpowers/specs/ict-service-support-postgres-prod-spec.md §3.10. Bracket: docs/superpowers/brackets/fi245-postgres-production.md. Tier 3 — deps SF-2 + SF-3 + SF-27 Done.

## Spec slice
1. BFF SSE endpoint (`GET /events` — EventSource stream): auth bằng access token (EventSource không set header được → query param `?access_token=` hoặc cookie — chọn 1, verify JWKS như API thường).
2. **Nguồn event = Kafka (SF-27)**: Java/Go đã publish `order-events` + `batch-events` lên Kafka; SF-27 đã dựng BFF consumer group `bff-realtime` bridge ra internal EventEmitter — SF-10 chỉ cần: EventEmitter → SSE stream (filter theo event type relevant cho FE: order.assigned/cancelled/completed/failed/redelivered + batch.created/transitioned), map envelope `{eventId,type,occurredAt,source,payload}` → SSE payload `{type, payload, ts}`. KHÔNG cần NOTIFY/LISTEN, KHÔNG đụng Java/Go.
3. FE: hook `useRealtimeEvents` — subscribe, D1 orders table + D2 fulfillment refetch (RTKQ invalidates) khi event relevant; không optimistic-update phức tạp (refetch là đủ).
4. Reconnect tự động (EventSource native) + fallback polling 30s nếu SSE fail liên tục (kể cả khi Kafka consumer lỗi).
5. E2E spec mới: mutate ở context A → context B thấy update (2 pages cùng lúc) — chạy được cả khi KAFKA_ENABLED=0 (producer off thì BFF vẫn có thể publish local EventEmitter từ mutation route của chính mình — dual-source: Kafka event HOẶC local mutation hook, chọn đơn giản).

## ACCEPTANCE (user-visible)
- 2 tab mở (2 user hoặc cùng user): tab A gán shop/complete đơn → tab B thấy row đổi trong ~1-2s, không F5.
- Giữ tab idle 5 phút → vẫn nhận event (reconnect hoạt động).
- SSE chết (kill BFF tạm) → FE fallback polling, không crash.
