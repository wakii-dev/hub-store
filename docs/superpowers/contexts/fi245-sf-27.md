# FI-245 SF-27 Context Pack — Kafka event bus trung tâm
> Epic spec: docs/superpowers/specs/ict-service-support-postgres-prod-spec.md §3.27. Bracket: docs/superpowers/brackets/fi245-postgres-production.md. Tier 2 — deps SF-2 (orders Postgres) + SF-3 (batches Postgres).

## Spec slice
1. **Compose infra**: kafka (KRaft mode — KHÔNG zookeeper) + kafka-ui (chỉ dev convenience) trong docker-compose.yml, healthcheck; 3 topics khai báo lúc init: `order-events`, `batch-events`, `notification-events` (partitions=1, RF=1 — single-node dev là đủ).
2. **Event envelope chung** (đặt nơi cả Java + Go import được — vd packages/shared hoặc copy nhỏ 2 bên với doc khớp schema): `{eventId (uuid), type ("order.assigned"|"order.cancelled"|"order.completed"|"order.failed"|"order.redelivered"|"order.created"|"batch.created"|"batch.transitioned"), occurredAt (ISO-8601), source ("fulfillment"|"batching"|"bff"), payload (object)}` — JSON, message key = orderCode/batchCode (đảm bảo thứ tự per-entity).
3. **Producer Java** (fulfillment): publish sau mutation order thành công (ASSIGNED/CANCELLED/COMPLETED/FAILED/redelivery). **Producer Go** (batching): publish sau CreateBatch/Transition thành công. Best-effort + log warn khi fail — KHÔNG retry phức tạp, KHÔNG outbox, KHÔNG block nghiệp vụ (saga direct gRPC giữ nguyên).
4. **KAFKA_ENABLED flag** (mặc định `false`): false → producer/consumer no-op trả về thành công, KHÔNG lỗi, không cần kafka chạy — môi trường dev nhẹ + E2E cũ không vỡ. true → compose kafka phải lên trước (depends_on + healthcheck).
5. **Consumer BFF**: consumer group `bff-realtime` subscribe `order-events` + `batch-events` — expose callback/emit cho SSE layer (SF-10 dùng; nếu SF-10 chưa merge thì chỉ cần emit ra internal EventEmitter — giao diện sạch).
6. `.env.example` thêm `KAFKA_ENABLED`, `KAFKA_BOOTSTRAP_SERVERS` (default `localhost:9092`).
7. KHÔNG đổi gRPC contract; KHÔNG đổi REST shape; KHÔNG event-sourcing; KHÔNG đụng saga compensation.

## ACCEPTANCE (user-visible)
- `KAFKA_ENABLED=true` + compose up → kafka-ui thấy topics; assign/hủy/hoàn tất đơn trên D1 → event `order-events` hiện trong kafka-ui; tạo/đổi batch → event `batch-events`.
- `KAFKA_ENABLED=false` (mặc định) → app chạy trọn vẹn, không lỗi console, không cần kafka container.
- Stop kafka container giữa chừng khi enabled → mutation nghiệp vụ VẪN thành công (best-effort), log cảnh báo, không crash.
- E2E cũ + spec kafka mới (skip-mode) xanh.

## Boundary (KHÔNG làm)
- KHÔNG outbox pattern / exactly-once — best-effort là đủ mức này.
- KHÔNG cho Kafka vào path nghiệp vụ blocking (saga giữ direct gRPC).
- KHÔNG SSE/FE (SF-10 sở hữu), KHÔNG notification pipeline (SF-23), KHÔNG webhook publish (SF-26 tự publish qua producer của SF-27).
